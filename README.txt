============================================================
 个人全天候 ETF 量化资产配置与择时系统
============================================================

本程序回答的唯一核心问题是：

    「我这一整个 ETF 组合，现在值不值得增加风险资产？
      该加哪一类？加多少？分几批？还是继续 WAIT？」

最终决策对象是【整个组合】，不是某一只 ETF。
不接券商、不下单、不保存账户密码，只做数据、分析、信号与风险监控。


------------------------------------------------------------
一、怎么用
------------------------------------------------------------
1. 双击 GoldETFMonitor.exe（或文件夹里的 GoldETFMonitor.exe）。
   目标电脑不需要安装 Python，不会弹出黑色命令行窗口。

2. 第一次打开会提示「未填写持仓数量/成本，当前仓位按配置目标权重展示」。
   请点左侧「设置」→ 填写每只 ETF 的持有份额与成本价 → 点
   「保存全部设置并重新加载数据」。

3. 回到「组合总览」。**结论永远在最上面一张大卡里，5 秒就能看完**：

   ★【今天怎么做】——整屏最醒目的蓝框大卡（第一位置）
       · 一句话大字结论（34px）：今天买什么 / 今天不买 / 今天只做再平衡
       · 三个关键数字并排：今天投入多少元 ｜ 买哪只 ｜ 组合未来60日盈利概率
       · 为什么（最多 3 条）+ 下一次的触发条件
       · 今天不买时，用「※ 参考」一行注明"模型算出的最优是哪只多少元、为什么今天不做"

   一句话口径规则（避免"看到金额却不知道能不能买"）：
       只有【建议分批买入 / 小仓试探】才会在"今天投入"里出现金额；
       再平衡 / 防守 / 持有观察 / WAIT 时，"今天投入"一律显示 0 元、"买哪只"显示
       "不买"，理论最优只出现在"参考"行里。

   大卡下面才是支撑数据（时间紧张时不用看）：
   ① 总资产（ETF 市值 + 待投资现金）
   ② 【组合未来60日历史盈利概率】含样本外、95% 置信区间、样本数、期望、回撤
   ③ 【如果什么都不买 / 如果执行建议】两种做法的组合指标并排对比 + 一句结论
   ④ 【实际仓位 vs 战略目标】债券/股票/黄金/现金，标注超配/低配多少 pp
   ⑤ 【黄金】状态与建议

   顶部「新手模式」默认【已勾选】（首次运行即结论优先，参数不干扰）；
   取消勾选进入专业模式，可看到全部指标：详细 7 状态与三个独立问题、
   今天最值得配置、交易前后对比表、现金与不要追涨/抄底、ETF 明细表、
   四批进度、今日最终结论、数据源状态。
   专业模式标签页还包括：组合统计、相关性、风险贡献、再平衡与配置（含再平衡模拟）、
   边际组合分析（金额网格）、黄金与宏观、历史回测。

4. 想看细节：点「ETF 明细」看单只 ETF 的全部指标、图表、【买入质量】A/B/C/D/E
   与「边际组合分析」（那里逐档列出「新增 500 / 1000 / 2000 / … / 全部现金」
   元之后整个组合的概率/期望/回撤/质量各是多少，并标出本批建议金额）。

5. 点左侧「黄金ETF」＝【159937 黄金专项监控页】：把原本独立的旧版程序
   「159937 黄金ETF量化风险监控」**集成进主系统**（同一窗口、同一份数据快照，
   不额外联网、不重复下载、不新增数据源）。一页看全黄金：

   · 【当前状态】状态徽标 —— 已超配·暂停加仓 / 已达上限·只持有 /
     底部信号·受 5% 上限约束 / 正常参与；下面列「为什么」（最多 6 条真实依据）
     与「目前最重要的观察」（要满足什么才谈得上加仓）。
   · 【综合风险评分】0-100（越高下行风险越大）+ 市场状态 + 5 项风险分项；
     另有【黄金宏观评分】8 指标加权（50=中性）。
   · 【核心数据】当前价格 / 持仓数量 / 持仓成本 / 当前市值 / 浮动盈亏 /
     收益率 / 黄金仓位 vs 5% 上限 / 行情时间 + 成本基准与数据源。
   · 【黄金底部雷达（8 个条件）】逐条列出满足 / 未满足 / 数据缺失，并给出
     「未入底部信号 / 恐慌区 / 底部观察区 / 趋势反转确认区」四级判定。
   · 【159937 技术面与关键价位】均线、RSI14、MACD、ATR14、60日与52周高低、
     20日涨跌、相对价位、当前回撤，以及 MA10~MA200 / 60日高低 / 持仓成本
     到现价的百分比距离。
   · 【8 指标监控明细】趋势层 / 宏观层 / 情绪层 / 广度层，逐项给评分、权重、
     贡献与说明；数据缺失项不参与加权（权重重归一），绝不伪造。

   本页与前几轮一致：**不含走势图**（只做卡片 + 表格），数据全部来自同一次
   组合快照，因此与「组合总览」「ETF 明细」的数字永远一致。

一·五、第二阶段新增（让普通人一眼看懂）
------------------------------------------------------------
· 持仓口径修正：黄金按真实 1900 份计算；现金独立为第 4 项，
  债券/股票/黄金/现金 = 100%（示例：44.5% / 21.0% / 14.6% / 19.8%）。
· 组合账户隔离：config 中 portfolio.id（如 all_weather_01），
  不同组合的持仓/成本/现金/历史数据物理隔离（data/<组合ID>/），互不读取。
· 【今天到底怎么操作？】只输出 7 个状态：🟢建议分批买入 / 🟢小仓试探 /
  🟡持有观察 / 🟠暂停加仓 / 🔴防守·不要买 / 🔵再平衡 / ⚪WAIT 等待。
· 组合买入门槛 S/A/B/C/D/E：优先使用【独立事件去重样本外】60 日概率 ≥65%，
  叠加期望收益、盈亏比、样本数、风险、是否追高等条件。
· 数据一致性检查：份额/市值/总资产/现金/大类权重合计 误差 > 0.5% 时
  显示【数据一致性异常】并拒绝输出任何金额建议（WAIT / 数据异常）。
· 黄金硬上限 5%：超配时买入分强制为 0，只允许持有或再平衡，
  且清楚显示「黄金超配 +X.X 个百分点 ≈ ￥XXXX 元」。
· 允许「第一批 0 元」：WAIT 是合法结论，绝不会为了填满目标缺口而强制买入。

一·六、第三阶段新增（组合才是老板）
------------------------------------------------------------
核心变化：把「买哪只 ETF 胜率最高」彻底换成
「买这只 ETF 之后，我整个组合到底变好了没有」。

· 唯一真源：core/marginal.py 的 PortfolioSimulator。
  它用【当前真实持仓权重】构造组合，现金按 0 收益计入（现金拖累不被忽略），
  因此组合胜率不再被 ETF 满仓口径高估（示例：满仓口径 96.2% → 真实 94.3%）。
· 三个组合严格区分、互不混淆：
   ①【当前真实组合】= 现有持仓 + 待投资现金（回答"现在该不该买"只用它）；
   ②【本次交易后组合】= 在①上执行某笔买入/卖出之后（用于交易前后对比）；
   ③【最终战略目标组合】= 债券50%/股票45%/黄金5%/现金0 的假想组合，
      只作为"目标长什么样"的参照展示，**绝不**用来回答今天买不买。
  （示例：当前真实组合 60日概率 94.3%，战略目标组合参照 82.9%，两者完全不同。）
· 相似历史状态只识别一次：先用当前真实组合找出一批历史相似起点
  （kNN，无未来函数），所有买入方案共用【同一批邻居窗口】评估，
  避免「每换一个金额就重新挑邻居」造成的抽样噪声（曾造成 ±4pp 跳动）。
· 金额网格模拟：对每只候选 ETF，模拟
  0 / 500 / 1000 / 1500 / 2000 / 3000 / 4000 / 5000 元
  以及按可投现金 10%/25%/50%/75%/100% 生成的档位，
  每一档都重算整个组合的 20/60/120 日胜率、期望收益、最大回撤、波动率、
  Sharpe、分散度与 Portfolio Quality，再取【组合综合质量最高】的那一笔。
· 边际改善分（0-100，50 = 与不交易完全一样）：由
  60日概率/期望/1年回撤/波动/Sharpe/分散度/目标缺口 七项变化量加权得到。
  解决「组合质量在低波债券组合里顶格饱和、分辨不出 1 个百分点改善」的问题。
· 批次安全上限：单只第一批 ≤ min(可投现金×33%, 目标缺口×50%, 单只上限)，
  绝不一次把现金打光；模型最优金额超过上限时会在理由里写明
  「模型最优 X 元，但遵守分批纪律按 Y 元执行」。
· 四批阶梯分批：第 1 批在当前组合上模拟；第 2 批在「第 1 批已执行」的新组合上
  重新模拟并重算金额，所以各批金额可以不相等，市场恶化时后续批次自动 0 元（WAIT）。
· 再平衡也要模拟：黄金降到 10% / 8% / 5% 分别模拟整个组合质量，
  取质量最好且卖出最少的方案，不做「超配了就机械一次性清仓」。
· 交易前后对比：同时给出【什么都不买】与【执行建议后】的组合
  60/120 日概率、期望收益、1年回撤、波动与质量，并给出一句结论
  （「该交易改善整个组合」/「能改善但今天不执行」/「组合质量变差，禁止建议」）。
· 新增落盘：data/<组合ID>/portfolio_simulation.csv（候选×金额网格逐条结果）
  与 rebalance_simulation.csv（黄金各档位再平衡模拟），供事后复盘。

一·七、第四阶段新增（V4 验收修正：诚实优先）
------------------------------------------------------------
核心变化：把「概率很好看」换成「概率值得相信吗、模型到底有没有用」。

· 概率口径（首页/CLI/策略有效性页统一，全系统只有一个决策概率）：
  基础历史概率（不择时基准）→ 相似状态历史频率（研究参考）→
  重叠滚动OOS频率（研究参考）→ 【保守独立事件OOS概率 = 唯一决策主口径】。
  92.0%（重叠滚动OOS频率）与 92.8%（相似状态历史频率）只作研究参考，
  绝不参与任何买卖判断；决策只看独立事件去重样本外概率。
  决策口径 − 基础历史概率 ≤ 0 时明确显示
  【当前模型没有证明额外择时优势】，禁止把 90%+ 的高胜率当成"模型很准"
  ——那主要来自资产长期上涨。独立事件不足 30 个时标注【样本极少，仅供研究】。
· 逐日滚动样本外预测：每个交易日 t 只用 ≤t 数据做预测（20/60/120日），
  区分预测点数与独立信号数；概率校准按 5% 宽桶统计"预测 70% 是否真涨 70%"，
  并且【概率校准必须与基础率 Brier 基线比较】（Naive Base-rate 模型：
  永远预测基础胜率、什么都不算）。BSS≤0 时如实显示
  「模型校准未优于基础率基线」；旧的"Brier<0.25 即可接受"口径已废弃。
· 数据交叉验证：--validate-data 对每只 ETF 用同花顺+腾讯双源核对
  收盘/最高/最低/MA20/相对价位等，并逐 ETF 列出全部指标明细。
· 真实交易价与复权价分离：分析用前复权（adjusted），下单金额/份数/市值
  一律用真实未复权价（raw）。所有建议金额先换算成 100 份整数倍
  再反算实际成交金额（例如 1500 元 → 500 份 → 1577 元）。
· 可信等级综合判定（不打单一阈值分）：数据双源验证 + P0 报告齐备性
  + 独立事件数 + 95%CI 宽度 + 概率校准 + 四项择时优势证据的方向一致性
  + 敏感性（成本/相似距离/特征消融）。任何 P0 报告缺失或数据验证
  有差异时，最高只能判【观察级】。
· 合成测试场景与真实账户分离：TEST_REPORT 中所有 fixture 测试
  一律标注【测试场景：…（合成数据）】，真实账户检查用真实持仓。
· 小资金适配：某 ETF 100 份就超配时允许【暂不配置】；显示完整配置
  6 只 ETF 的理论最低资金与 2万/5万/10万的适配建议。
· 黄金再平衡按 100 份整数倍模拟（如卖出 1200/1300 份分别评估）。
· 回测修正：BACKTEST_REAL_6ETF.md 只从 511090 上市后开始
  （绝不与代理历史混算）；信号 T 日收盘生成、T+1 开盘成交；
  成本拆分为佣金+滑点（backtest.costs 可配置）。
· BPGDM 优先取**真实值**（用户配置 URL，其次 StockQ 镜像 $BPGDM；定义与 P&F 参数
  参考 StockCharts）；真实值不可用时另列**代理值**（约 30 只金矿股站上 200 日均线
  占比），两组字段**严格分离**：界面显示【BPGDM真实值：暂无数据】+
  【BPGDM代理值：XX%（代理定义：…）——【代理，仅供研究】】，绝不冒名。
  Gold Fear & Greed 与【黄金情绪代理】同样分开；
  黄金底部雷达条件②支持配置项
  gold.radar.use_sentiment_proxy_when_official_missing（默认 false）：
  官方 GVZ 不可用时是否允许用本地情绪代理（阈值 ≤40）替代判定，
  无论采用与否都会显示【官方值 / 本地代理 / 最终采用值 / 采用原因】。
  缺失数据在雷达中标注【未知】，不会被当成"不满足条件"。
· 各数据源的【数据日期】分开显示（A股ETF / 黄金 / DXY / 实际利率 各自标注）。
· 新增【策略有效性】页面：四概率 + 概率校准 + 模型相对基准提升 +
  系统可信等级（研究级/观察级/辅助交易级/实盘辅助级，硬门槛自动判定，
  不是买入等级）。模型若无择时优势，会如实显示。
· TEST_REPORT.md 新增四大类结果与【实盘前检查清单】（逐项真实评估）。

一·八、最终修正（概率口径与统计口径统一，不加新功能）
------------------------------------------------------------
本轮只做一件事：把概率口径彻底统一、把统计结论变得诚实、消除报告内部矛盾。

· 首页主概率 = 【保守独立事件样本外概率】：独立事件去重后的
  逐日样本外 60 日概率（显示独立事件数、95%CI、无条件基础胜率、
  模型相对基准）。重叠逐日频率只能作为辅助字段显示为
  「重叠滚动OOS频率」，绝不再被命名为"样本外盈利概率"。
  独立事件不足 30 个时，概率后面必须标注「样本极少，仅供研究」；
  模型相对基准 ≤ 0 时必须显示「当前模型没有证明额外择时优势」。
· 相似状态距离硬上限 3×：绝不为了凑够样本自动放宽。3× 以内样本不足时
  返回「样本不足/UNKNOWN」，不为生成概率强行使用更远的历史。
  只有显式修改配置 hist.allow_distance_relax 才允许手动放宽，
  且放宽后的概率必须显示「本次概率使用了超常距离样本，可信度降低」，
  并禁止被标为高可信。
· DATA_VALIDATION_REPORT 的【指标明细】与【交叉验证主源值】来自
  同一次数据计算（同一主源 K 线 + 同一 compute_all），完全一致；
  取不到的指标显示「未验证」，绝不允许"上面明细是 None、
  下面交叉验证又算出值"的矛盾。TEST_REPORT 的技术指标自检
  也引用同一套结果。
· 「实时」与「最新交易日」严格分开：数据日期不是今天时，一律写
  「最新交易日：YYYY-MM-DD」「最新收盘价：XXX」；只有真正拿到
  实时行情快照时才单独写「实时价：XXX（实时更新时间：…）」。
· TEST_REPORT 的 173/173 只表示【代码自检测试通过】，绝不解释成
  「策略有效」；实盘前检查清单中任何一项为「未验证」时保持未验证，
  不因自检通过而改判全部通过。
· 系统可信等级按硬门槛综合判定，当前为【研究级】：独立事件仅 14 个、
  逐日样本外相对基准为负、完整模型相对趋势基准 0pp、Walk-Forward 0pp、
  模型校准未证明优于基础率基线——在以上证据改变之前，
  禁止升级为观察级/辅助交易级/实盘辅助级。


一·九、样本门禁说明（为什么通常看不到股票买入建议）
------------------------------------------------------------
这是本系统【刻意保守】的设计，不是故障，也不是数据出错：

· 单只 ETF 想拿到买入评级（A/B 级），前提是「相似样本 ≥50 个」
  且「相似距离 ≤3×」。3× 是硬上限，超出后【不自动放宽】——
  宁可不给信号，也不用更远距离的历史样本凑数。
· 两个约束叠加后，单只 ETF 常常拿不到 50 个样本（例如实测
  城投债 13、30年国债 8、纳指 42、港股红利 15、创业板 26、黄金 5），
  于是买入质量一律判为「样本不足」，系统便不会给出股票 ETF 买入建议。
· 因此「概率看起来很高，却没有买入建议」并不矛盾：
  ① 那个 85.7% 是【整个组合】未来 60 日上涨的历史频率，
     而不用任何信号的基础率是 88.5%——模型相对基准 −2.8pp，
     高概率来自资产长期上涨，不是择时能力；
  ② 组合买入门槛里还有一条「至少一只股票ETF 买入质量≥B 且
     Entry Score ≥70」，在上述样本门禁下几乎不可能满足；
  ③ 若黄金同时超过 5% 硬上限，当天只做再平衡，新增资金一律不投。
· 报告与界面都会显式打印这段说明，避免被误读成「软件坏了」。

一·十一、买入权限闸门（BUY PERMISSION GATE，最高优先级）
------------------------------------------------------------
**可信等级决定买入权限，不是买入等级。研究级即使组合模拟发现某笔交易
可能改善组合，也只做研究参考，不开放实际买入建议。**

· 硬约束：当系统可信等级为【研究级】（或低于开放门槛）时，
  最终输出禁止出现「建议分批买入」「小仓试探」；
  允许的最终状态只有：持有观察、暂停加仓、防守·不要买、再平衡、WAIT。
· PortfolioSimulator 仍会继续模拟理论买入金额，但只作「研究参考」，
  不能转换成实际 BUY 状态。例如允许显示：
  「研究参考：模型模拟 30年国债ETF 1500 元后组合质量最高」，
  但最终结论必须是：
  「研究级：当前不开放买入权限，因此今天不执行」。
· 只有可信等级达到预先定义的更高等级，才允许开放「小仓试探 / 建议分批买入」。
  开放门槛由 config.trust.buy_permission_min_level 定义，默认【辅助交易级】；
  即可信等级 ≥ 辅助交易级 才开放买入，研究级 / 观察级一律不开放。
· 该闸门不改变任何统计结果：prob_used=85.7%、-2.8pp、BSS=-0.1591、
  研究级 等一律照旧——它是"权限"约束，不是"重新判定有效性"。
· 可信等级由 `--validate-strategy` 计算并持久化到 `data/strategy_trust.json`，
  运行期决策直接读取它；若该文件缺失（从未做过策略验证），一律按最保守的
  【研究级】处理（即不开放买入权限），绝不"默认放行"。

------------------------------------------------------------
一·十三、交易价值重构（Trade Value / BUY-SELL OOS / 影子交易）
------------------------------------------------------------
本轮**不是**界面优化、**不是**把回测收益做高，而是把系统从
「预测未来 60 日组合是否上涨」升级为
「**判断一笔真实交易，相对【什么都不做 / WAIT / 继续持有】是否真的提高整个
组合的风险收益结果**」。核心公式：

    Trade Value = 执行交易后的组合结果 − 不执行交易的组合结果

· **三类预测目标**：Direction（涨跌）/ Incremental Return（相对 WAIT 多赚多少）/
  Incremental Utility（相对 WAIT 的风险收益质量提升）。后两者才是交易决策核心。
  输出的增量字段：delta_return_20/60/120、delta_max_drawdown、delta_volatility、
  delta_sharpe、delta_sortino、delta_portfolio_quality、delta_transaction_cost。
· **四类基准同场比较**：Benchmark 0 = WAIT（当前真实组合原地不动）、
  Benchmark 1 = 固定 50/45/5、Benchmark 2 = 现有趋势基准 C、Benchmark 3 = 优化模型。
  不能稳定优于 WAIT，就不许宣称有交易优势。
· **严格 Walk-Forward（禁止全样本调参）**：训练窗 504 日、测试窗 20/60/120、
  **PURGE + EMBARGO**；60 日事件间隔 ≥60、120 日 ≥120，禁止用重叠窗口冒充样本。
  参数只在训练集选择后冻结（见 PARAMETER_SENSITIVITY_REPORT.md）。
· **主口径区间**：正式组合交易策略验证只用 **2023-06-13 ~ 2026-09-30**
  （真实六 ETF 共同区间，802 交易日）；更早历史只用于单资产/指标/宏观研究与参数预热。
· **成本三档**：LOW / BASE / HIGH 分别重跑；只在极低成本下成立的策略一律判
  「对交易成本敏感，不适合实盘」。
· **数据新鲜度闸门 DATA_FRESHNESS_GATE**：逐项检查 ETF 收盘 / ETF 实时 / 黄金 /
  DXY / 实际利率 / GVZ / BPGDM 的 data_date；关键行情陈旧 → WAIT / DATA_STALE，
  **禁止 BUY**；没有真正实时行情时必须写明「只能给下一交易日计划，不能称实时买卖建议」。
· **决策闸门链（任一失败即降级，绝不绕过）**：
  DATA GATE → FRESHNESS GATE → PORTFOLIO CONSISTENCY GATE → STRATEGY TRUST GATE
  → TRADE VALUE GATE → RISK GATE → POSITION LIMIT GATE → FINAL ACTION
  （FINAL ACTION ∈ BUY / WAIT / HOLD / REDUCE / REBALANCE / DATA_STALE；WAIT 永远合法）。
· **影子交易 SHADOW TRADING**：每日记录「如果当时执行会怎样」，落地
  data/shadow_trade_history.csv，**不真正下单、绝不修改真实持仓**。
· **市场状态分层**：所有动作按 Risk On / Normal / Risk Off / Crisis 分别统计。
· **代理值不进正式模型**：BPGDM 代理 / Fear&Greed 本地代理 / GVZ 代理**一律不进入**
  trade_value / buy_model / sell_model / policy_evaluator（代码级可验证），
  只能作研究参考或 UNKNOWN。
· **本轮结论（如实保留）**：六 ETF 共同区间内 60 日可用独立事件仅 2 个，
  相对 WAIT 的增量不具统计意义 → **不升级、保持研究级**；
  且 BUY 与 SELL 的相对增量均未被证明为正。


------------------------------------------------------------
一·十四、事件流水线审计（查清「为什么只有 2 个独立事件」）
------------------------------------------------------------
本轮**不新增指标、不改策略阈值、不降低研究级门槛、不把研究级改成可 BUY**；
唯一目标：查清 2023-06-13 ~ 2026-09-30（802 交易日）中 60 日 Trade Value OOS
最终只有 2 个独立事件的原因，并修正验证体系里的结构性问题。

· **根因（已定量归因）**：旧口径 `_fold_events()` 把「事件」定义为
  **walk-forward 折的 test_start**——802 日扣除 504 日训练窗后只剩 ~288 日，
  60 日测试窗只能切出 3 折；BUY 再排除 Risk Off/Crisis → **2**。
  **这不是「模型只发现 2 次机会」**，而是事件被死死绑在折数上、与模型信号无关。
· **修正**：事件改为「**模型真实信号日**（逐日分类）+ 间隔 ≥h 严格去重」，
  并同时构造 BUY / SELL / REBALANCE candidate 与 WAIT / HOLD / NO-REBALANCE 反事实。
· **15 级事件漏斗**（见 EVENT_FUNNEL_REPORT.md）：逐级给出 输入 / 进入 / 淘汰 /
  淘汰比例 / 淘汰原因 Top10，不再只给最后那个 2。
· **独立事件的物理上界**（最关键的一条）：
  上界 = (总交易日 802 − 预热 252 − 周期 h) ÷ h
  → 20 日 **27** / 60 日 **9** / 120 日 **4**。
  **即『独立事件 ≥ 30』在现有数据长度上物理不可达**——这是数据长度问题，
  不是模型无能，也不是阈值该被降低（禁止为凑样本降低独立间隔）。
· **候选 / 可执行双层**：`candidate_event`（模型认为有机会）与
  `executable_event`（再经安全/成本/仓位/新鲜度/权限放行）**分别统计**，
  不再把最终 BUY/SELL 直接当成 OOS 样本。
· **研究层 / 生产层双口径**：RESEARCH_POLICY 回答「这条规则有没有历史增量价值」
  （**不受执行权限约束**）；PRODUCTION_POLICY 回答「今天实际允不允许做」。
  研究级下生产层 BUY 可执行事件恒为 0，但**研究层样本不再被生产权限污染**，
  从根上拆掉「权限过严 → 无样本 → 无法证明 → 永远研究级」的循环。
· **模型阶梯 Model 0-4**（同一 OOS 事件集合）：WAIT / 简单趋势 / 当前完整模型 /
  去宏观代理（≡ 当前模型，因本模型本就不含代理）/ 精简模型。
  结论：**增加复杂度没有得到回报**（最简可用 = Model 1）。
· **事件定义稳定性**：对关键阈值做 ±5%/±2%/0/+2%/+5% 扰动，只标记
  「事件定义敏感」，**绝不挑选表现最好的一组参数**。
· **四基准 D−A / D−B / D−C**：D=优化模型、A=WAIT、B=固定 50/45/5、C=简单趋势；
  只在 3 折上比较，**样本极小，仅作方向性参考**。
· **最终结论（未放宽）**：主判定仍为「② 数据样本不足 → 保持【研究级】」；
  BUY / SELL / REBALANCE 三个动作 60 日 95%CI **全部横跨 0**；
  不为了得到 BUY 而修改任何门槛。


------------------------------------------------------------
一·十五、执行台账（「我卖出后，程序怎么知道我卖了？」）
------------------------------------------------------------
本程序**没有任何券商/成交接口**，它「知道持仓」的唯一入口是 config 里的
`assets[].shares`（在「设置」页的持仓表里填）。因此有一个容易困惑的现象：

· 界面显示「今天只做一件事：卖出黄金 1,300 份」——它其实是一句
  **计划 / 目标**（在「黄金必须回到战略上限 5%」的前提下，按 100 份整手、
  并对 10%/8%/5% 三档做组合模拟后择优的最小卖出量），
  **不是成交回报，也不是委托**；
· 若你真的卖出后**不去改持仓份额**，程序下次仍读到旧份额，
  于是会**继续重复同一条建议**——因为它根本不知道你已经执行了。
· **执行台账**补上这一环：在「组合总览」第一屏结论卡下方点
  「**我已按此执行（更新持仓与现金）**」，确认后程序会
  ① 按该笔建议减少持仓份额；② 现金按成交额增加；
  ③ 写一条**带日期的台账**（data/execution_ledger.json），并自动重算。
  于是同一条建议不会再天天重复出现。
· 台账状态显示在两处：第一屏结论卡「执行台账：…」一行；
  CLI 报告「执行台账 ：…」一行（未执行会明确写「尚未执行」）。
· **硬约束**：只在你**点击并确认**后才改本地持仓记录，
  **绝不自动下单、绝不联网**；写 config 前自动备份；
  份额不得为负、卖出不得超过持有；卖出后份额按 100 份整手扣减。
· 说明：本台账只是「本地持仓记录 + 操作留痕」，**不追踪真实成交价与费用**；
  真实成交以券商为准，卖出手续费/滑点未计入本地现金。


------------------------------------------------------------
一·十六、指令栏（你主动对系统「说话」的渠道）
------------------------------------------------------------
上一节的按钮**只接受程序自己那条建议**。但很多时候你要表达的是别的意思：
「我只想卖 800 份」「我 8.62 成交的」「我账上还有 20 万现金」「这条今天先不做」——
这些它原来都听不到。**指令栏**就是补这个缺口：

· 位置：「组合总览」第一屏结论卡下方，一个输入框 + 「执行」按钮（回车即触发）。
· 在框里打**一句人话**，它解析成动作：

    你说                    它做什么
    卖黄金800@8.62       →  登记卖出 800 份；@ 后是成交价，同时把现金 +6,896 元
    买纳指500            →  登记买入 500 份（不给成交价则不动现金）
    减仓 城投债 1000      →  卖出 1,000 份（支持简称：纳指/红利/创业板/国债）
    现金20万             →  把现金登记为 200,000 元（**补全超配判定的分母**）
    总资产30万            →  登记总资产，现金 = 总资产 − ETF 市值
    上限黄金6%            →  把黄金硬上限从 5% 改为 6%
    目标 债50 股45 金5     →  改战略目标比例
    忽略 / 搁置           →  记一条「暂不执行」台账，不动持仓
    备注 今天没空          →  记一条备注，不动持仓

· **宽容解析**：全角数字（８００）、千分位（1,300）、万元（20万）、
  各类简称都能懂。
· **绝不乱猜**：标的歧义（「卖债800」对应两只债）或缺份数时，
  它**直接说「没听懂」并给示例**，不改动任何东西。
· **二次确认**：涉及买卖/改参数会先弹一句中文预览（将把什么改成什么），
  确认后才写入；成功后再自动重算组合。
· **硬约束**：与台账一致——只改本机记录，**绝不自动下单、绝不联网**，
  写 config 前自动备份。自检第 47–51 项专门守着解析与这条禁令。


------------------------------------------------------------
一·十七、实时持仓（改份额 → 立即判断「该加/该减/持有」）
------------------------------------------------------------
需求原话：「能不能实时输入每个 ETF 的份额表示目前持仓，然后工具再判断
是否要增加减少。」——第一屏结论卡下方就是这张**可编辑的持仓表**：

    名称 | 类别 | 持有份额 | 现价(日线收盘) | 参考现价(盘中) | 市值(元) |
    当前权重% | 目标权重% | 判断

· **实时**：改任意一格的「持有份额」→ 市值 / 当前权重 / 逐只判断**立即重算**。
  不联网、不重跑模型（只用当前快照现价），因此是秒级刷新。
· **口径一致**：判断复用与首页**完全相同**的再平衡判定器
  （core/signals.rebalance_plan），阈值也一致，不会出现「面板说加、首页说减」。
· **两层分工**（务必分清）：
    - 再平衡级（加 / 减 / 持有 + 偏离 pp）→ **完全由份额决定**，本面板实时重算；
    - 模型级「今日买入权限」→ 取决于**当日市场状态**，**与份额无关**，
      本面板沿用首页当日结论（面板下方单独一行说明）。
· **保存**：改动**先只用于本次判断**；点「保存为新持仓」才写入
  config/config.json（写前自动备份 + 二次确认）。点「放弃改动」恢复原持仓。
· **安全**：仅改本机持仓记录，**绝不自动下单、绝不联网**；
  份额为负自动规整为 0、非数字保留原值、绝不因输入错误而崩。
  自检第 52–55 项守着重算正确性、即时刷新、边界与「纯计算不写盘」。

一·十八、价格口径：哪个价是「判断用」，哪个只是「参考」
------------------------------------------------------------
常被问：「持仓的现价是真实价格吗？是联网的实时价吗？」——分开答：

**（1）判断用的价 = 日线收盘价（前复权），真实联网抓取。**
  链路：data_sources/etf_source.py 取日线K线（主 同花顺扶摇 → 备 腾讯
  fqkline 前复权 → 三备 新浪 getKLineData）→ core/signals.etf_snapshot
  内 `price = ind["close"][-1]`（最后一根日K收盘），`data_time` = 该K线日期。
  · 它是**真价**（不伪造、不插值），但**不是盘中实时 tick**；无行情推送。
  · 缓存有效期 `data_sources.cache_ttl_minutes.etf` 默认 **60 分钟**
    （已由 720 分钟/12 小时下调，避免盘中看到的收盘价过期太久）。
  · 「立即刷新」按钮**始终强制联网**、忽略缓存；自动刷新/启动走缓存优先。

**（2）仅供参考的价 = 盘中实时报价（默认开启，可关）。**
  链路：data_sources/realtime_quote.py 批量取腾讯 qt.gtimg.cn（一次请求取全部
  标的，短超时 3 秒、不重试），带回**行情时间**与涨跌幅。
  · **硬边界**：它**只用于界面多显示一列「参考现价」，绝不参与**权重、偏离、
    超配、再平衡、BUY 权限等**任何判断**；判断一律用上面的日线收盘价，
    以保持与策略（20/60/120 日日线口径）一致。
  · 取不到就留空（显示「—」），**绝不影响主流程**。
  · 关掉：config/config.json 设 `data_sources.realtime_quote = false`。
  · 自检第 61 项专门验证「失败/异常一律返回空、模块不写盘不下单」，
    第 59 项验证「把参考价设成 999 或干脆没有，权重与逐只判断完全一致」。

**（3）界面怎么自查时效**：持仓面板上方有一行「价格口径」，
  写明「判断用『现价(日线收盘)』：YYYY-MM-DD 收盘（数据源）」+
  「『参考现价(盘中)』行情时间 YYYY-MM-DD HH:MM，仅供参考，不参与判断」；
  组合总览顶部另有「数据日期 / 获取时间」。**都刻意不写「更新时间：今天」**。
  自检第 56–61 项守着解析、容错、TTL、不参与判断、文案齐备与边界。

一·二十二、取数通道自动降级（2026-10-08 补：接上外部节点后新增）
------------------------------------------------------------
背景：某些数据源（如 FRED）的前置 WAF 会校验「**你自称是谁**」和
「**你的握手像谁**」是否自洽。"浏览器 UA + 非浏览器握手"是典型爬虫特征，
会被直接掐断（实测 WinError 10054 / 读超时）——但换成与自身一致的"诚实 UA"
或系统 curl，同一秒就是 HTTP 200。**这是通道问题，不是"源不可用"**。

现在程序按三层自动依次尝试，成功后记住该主机该走哪一层：
    ① 浏览器 UA（直连，多数源需要）
    ② 诚实 UA（python-requests/x 等，让 UA 与指纹自洽）
    ③ 系统自带 curl.exe（Win10 1803+ 自带）

  · 只有**连接级失败**或 401/403/429/451 才换下一层；
    404/5xx 换通道没意义，直接如实返回状态码。
  · **实际生效的通道会写进【说明】列**（如"取数通道：诚实 UA（WAF 一致性校验）"），
    你能看到这份数到底是怎么取回来的——走没走兜底，一目了然。
  · 三层都失败 → 照旧如实报错＋原因，**绝不用缓存/代理冒充实时**。
  · 开关：config.json 的 `app.ua_fallback` / `app.curl_fallback`（默认都开）。

BPGDM 真值（StockQ）：
  · StockQ 的 en/cn/fr/es/www 各域名对本机 **一律 403**（按 IP/机房段拦截），
    换 UA / Referer / HTTP 版本、改用系统 curl 均无效。
  · 此时程序经公共阅读器 `r.jina.ai` **转发**取**同一个页面**，
    仍能拿到**真实 BPGDM**（2026-10-08 = 40.54；MA5/MA20/MA60 与 StockQ 官方值一致）。
  · 来源仍是 StockQ，只是多了一跳中转——【说明】列会明确写「**经转发**」，
    绝不隐去；转发也不可用时才退回代理（且代理**不参与评分**）。

来源页截图存证（离线留证）：
  · 用**本机已装的 Chrome/Edge** 无头模式逐源截图，不下载任何浏览器：
        python tests/shot_sources.py                  # 全部来源
        python tests/shot_sources.py --only=gold,dxy  # 只补拍个别源
  · 产出 __shots/sources/<key>.png 与 INDEX.md；**打不开的页面（403/超时）
    也照样截图留证**，INDEX.md 里标 ✅/❌ 与原因。

配置：核对网址可用 data_sources.verify_url.<key> 覆盖（换成你习惯的站点）。


一·二十三、ETF 主源（同花顺扶摇）并发限流修复（2026-10-08 补）
------------------------------------------------------------
背景：管道默认 3 路并发预取 6 只 ETF（`app.fetch_workers`）。实测同花顺扶摇对
**并发突发**限流很重：

  · **串行**请求：每只 6~10 秒，6 只全部成功（1212 / 803 / 1079 根日线）；
  · **3 路并发**请求：单次响应被拖到 30~50 秒，超过取数硬超时（timeout+1.5s），
    被判为「连接级失败」→ 连续 2 次即触发**主机熔断**（15 分钟），
    其余标的全部秒级快速失败 → **静默回落到腾讯证券**（历史更短，只有约 640 天）。

后果很隐蔽：主源明明可用，却因为并发被限流而**丢掉长历史**，
「真实六 ETF 共同区间」从 803 天缩到 640 天，事件审计窗口被悄悄砍掉一半。

修复（`data_sources/etf_source.py`）：
  · 把扶摇的 HTTP 请求在**进程内串行化**（`_THS_LOCK`，只允许一个在飞），
    从根上避免并发突发被限流；
  · 扶摇超时单独放宽（`data_sources.ths_timeout_seconds`，默认 20s），
    避免"慢但能成功"的请求被硬超时误杀进而熔断；
  · 其余标的与其它源（腾讯/新浪）行为不变，仍是「主源 → 备源 → 缓存」。

效果：同样 3 路并发下，6 只 ETF **全部**走扶摇拿到长历史（实测 43.8s 内 6/6），
打包版自检的「真实六 ETF 共同区间」回到 800+ 天。

------------------------------------------------------------
四、必须遵守的原则（已写进代码逻辑）
------------------------------------------------------------
1.  组合优先：单 ETF 机会分再高，也要由组合层决定买不买、买多少。
2.  目标仓位 ≠ 当前必须买满。股票低于长期目标但市场不适合，
    程序必须输出 WAIT —— 这是合法且常见的结论。
3.  低位置 ≠ 可以买。必须叠加「止跌确认」，否则输出
    「极度超跌，但尚未止跌」并拒绝抄底。
4.  高胜率 ≠ 可以重仓。同时看盈亏比、最大回撤、样本可信度、
    样本外胜率，并与「无条件基准胜率」对比。
5.  黄金永远 ≤ 5%。即使底部雷达 8/8 满格，也只能持有、不再增加。
6.  不追涨：1年与2年相对价位都在高位 + 20日大涨 + BIAS 明显为正
    + WR 超买 → 标记「高位强趋势」，禁止新增，但不机械卖出。
7.  再平衡不机械执行：偏离超阈值先观察，还要看趋势、波段顶底、
    风险贡献与历史统计，再决定持有 / 减仓 / 再平衡。
8.  分批投入：新增风险资金默认分 4 批，条件变差可以停在第 1 批。
9.  绝不使用未来函数。每个信号只使用当天及以前已经发生的数据。
10. 绝不用假数据。数据源不可用时显示「暂无数据」或「数据源异常」，
    不会为了界面好看而填 0 或随机值。
11. 三个问题是独立的：是否投入新增资金 / 是否再平衡 / 是否降低超配资产。
    可以「不投入新资金 + 需要再平衡」，但绝不会出现
    「YES 买入 + 同时不投入任何资金」这种自相矛盾的状态。
12. 数据口径出错时先修数据：持仓/总资产/现金/权重合计不一致时，
    程序拒绝输出任何买入金额建议，只显示【数据一致性异常】。
13. 首页优先使用独立事件去重后的样本外60日概率；重叠滚动OOS仅作为
    辅助统计。样本外不可用时明确写「样本外统计尚不可用」并下调买入信心。
14. 概率校准必须与基础率 Brier 基线比较（Naive Base-rate 模型）；
    BSS ≤ 0 时如实显示「模型校准未优于基础率基线」。
15. Portfolio Entry Score 只是 0-100 的辅助分，**不是胜率**；
    80 分 ≠ 80% 胜率，界面与报告都会明确标注。

------------------------------------------------------------
六、海外数据源不可达时怎么办（首次加载会不会卡住）
------------------------------------------------------------
国际金价、美元指数、BPGDM 金矿股广度都来自 Yahoo。部分网络环境访问不到它，
程序对此有专门处理，**不会卡住**：
· 加载前先做一次 6 秒上限的连通性探测；不可达就立即熔断该主机；
· 熔断后同主机的其余请求秒级跳过，不再"每个标的各超时重试 3 次"；
· 宏观加载有总时间预算，超预算的项直接跳过并写明「已跳过（显示暂无数据）」；
· 首次完整加载通常在 25 秒内完成，ETF 行情与官方利率数据完全不受影响。
结果会如实呈现：海外三项标注「数据源异常 / 暂无数据」，其余标注「本次联网获取」。
网络恢复后**重启程序**即可立即重试（熔断只作用于当次运行的进程）。
相关参数都可在 config/config.json 的 app 段调整：
host_fail_threshold / host_block_minutes / host_probe_timeout / macro_budget_seconds。

七、已知限制（诚实声明）
------------------------------------------------------------
· 30 年国债 ETF（511090）2023 年才上市，因此组合可回溯历史约 3 年，
  2 年以上统计的可信度会下降，界面会明确提示。
· 国际金价 / 美元指数 / BPGDM 依赖 Yahoo，在受限网络下可能整体不可达；
  此时这三项显示「暂无数据」，程序其余部分照常工作（详见上一节）。
· Gold Fear & Greed 官方接口在部分网络环境不可用，此时显示「暂无数据」，
  并改用本地代理指标（会在界面上标注「本地计算」）。
· BPGDM 默认使用**代理值**（约 30 只金矿股站上 200 日均线占比，
  界面标注【代理，仅供研究】，非真实 BPGDM）；GVZ 依赖 CBOE / Yahoo / FRED 等源，
  在受限网络下可能不可达，此时显示「暂无数据 / UNKNOWN」，绝不伪造。
· 所有概率都是「历史条件频率」，不是对未来收益的承诺。
